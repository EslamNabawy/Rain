# ADR-008 - File Transfer Uses Streaming Sinks And Backpressure

Last updated: 2026-06-03

## Context

Rain transfers files over WebRTC data channels. Large transfers can create memory pressure, data-channel buffer pressure, and cleanup problems.

## Problem

File transfer needs deterministic behavior for large files and slow receivers. Unbounded buffered sends or per-chunk sink churn can destabilize the app.

## Options

1. Keep current chunk loops and rely on small files.
2. Move file bytes through Firebase.
3. Keep WebRTC data channels and add streaming receive sinks plus send backpressure.

## Decision

File transfer stays on WebRTC data channels and uses:

- persistent receive sinks,
- temp file lifecycle,
- data-channel high/low water marks,
- pause/resume send loop,
- progress batching,
- idempotent cleanup.

## Consequences

- Firebase remains signaling/metadata only.
- Large transfers become bounded by explicit budgets.
- Tests must simulate slow receivers, cancel, close, and failure.
- Transfer diagnostics must report buffer pressure and cleanup result.
