# ADR-005 - Firebase Call Lease Manager Is The Single Lease Authority

Last updated: 2026-06-03

## Context

Rain uses Firebase signaling artifacts for call rooms, inboxes, pair locks, and user locks. False busy and stale lock behavior are release-critical risks.

## Problem

Lease claim, conflict inspection, stale repair, and terminal release can be triggered from multiple paths. Without one owner, stale locks can block calls or live locks can be deleted incorrectly.

## Options

1. Keep lease logic distributed across runtime and adapter methods.
2. Move all call signaling to Cloud Functions.
3. Keep Spark/free-tier compatibility and centralize client-side lease authority in `CallLeaseManager`.

## Decision

`CallLeaseManager` is the single lease authority. It owns:

- lock claim,
- conflict inspection,
- stale repair,
- rollback,
- matching-`callId` release,
- lease diagnostics.

## Consequences

- Busy is returned only after the referenced room is inspected.
- Cleanup is safer because matching `callId` is the ownership boundary.
- Spark/free-tier remains supported.
- RTDB rules and emulator tests become mandatory for confidence.
