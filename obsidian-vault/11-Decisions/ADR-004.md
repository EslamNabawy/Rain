# ADR-004 - Call Runtime Uses Coordinator Architecture

Last updated: 2026-06-03

## Context

[[VoiceCallRuntime Refactor Plan]] identifies `VoiceCallRuntime` as a high-risk runtime path that currently mixes start preflight, leases, media, terminal cleanup, renderer state, UI-facing state, and diagnostics.

## Problem

Keeping all call behavior in one runtime makes call bugs difficult to isolate and increases regression risk. Voice and video calls require stable ownership boundaries before further UI or media changes.

## Options

1. Keep `VoiceCallRuntime` as the single owner and add more tests.
2. Rewrite the call runtime from scratch.
3. Use strangler refactoring and extract coordinators around existing behavior.

## Decision

Use coordinator architecture through:

- `CallStartCoordinator`
- `CallLeaseManager`
- `CallMediaCoordinator`
- `CallTerminalReconciler`
- `CallDiagnosticsRecorder`

`VoiceCallRuntime` remains as an orchestration facade until responsibilities are migrated and old paths can be deleted safely.

## Consequences

- Call logic becomes testable by responsibility.
- Migration can happen incrementally without a full rewrite.
- More interfaces will exist, but they map to real runtime risks.
- UI polish waits until terminal and media state are stable.
