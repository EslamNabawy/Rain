# ADR-009: Production Readiness Vault Owns Audit Execution

Date: 2026-06-03

## Context

Rain has accumulated many plans, fixes, release attempts, call reliability changes, Firebase rule changes, UI changes, and diagnostics changes. The project needs one execution system that converts the audit into tracked work.

Related: [[Original Audit]], [[Master Roadmap]], [[Audit Resolution Tracker]], [[Project Memory]].

## Problem

Without a living execution vault, important findings become scattered across chat history, code comments, GitHub workflow logs, and local diagnostics. This makes it hard to know which defects are fixed, blocked, risky, or release-critical.

## Options

1. Keep docs in ad-hoc plan files.
2. Use external project management only.
3. Use an in-repo Obsidian vault as the source of truth and connect it to CI validation.

## Decision

Use `/obsidian-vault/` as the authoritative production-readiness execution vault. Every audit issue maps to an epic, feature, task, subtask, risk, and tracker row. The vault checker validates required notes and wiki-link targets.

## Consequences

- Documentation becomes part of the project artifact.
- New work must update [[Backlog]], [[Active Sprint]], [[Project Memory]], and affected feature notes.
- Release decisions must reference [[Release Gates]], [[Production Readiness]], and [[Audit Resolution Tracker]].
- This adds maintenance cost, but it reduces lost context and hidden regressions.
