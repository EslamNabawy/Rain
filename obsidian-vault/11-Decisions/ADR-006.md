# ADR-006 - Presence Resolver Is The Source Of Peer Availability Truth

Last updated: 2026-06-03

## Context

Presence controls direct connect, call eligibility, recovery behavior, and offline connection request notifications.

## Problem

UI friend state can become stale after app close, network loss, or old session heartbeat writes. User actions need fresh backend availability decisions, not presentation-only online flags.

## Options

1. Trust local friend online state for all user actions.
2. Require connected WebRTC session before calls or requests.
3. Use a dedicated presence resolver that checks fresh backend availability before sensitive actions.

## Decision

Use `PeerAvailabilityResolver` as the source of peer availability truth for user-triggered connect, call, and offline request actions.

## Consequences

- Online UI state remains presentation-only.
- Calls require fresh online presence, not necessarily an already-connected chat lane.
- Offline request notifications require stale/offline presence plus user confirmation.
- Presence unknown fails closed with a user-facing message.
