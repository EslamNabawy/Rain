# ADR-002 - Firebase Spark Tier Constraint

## Context

The project owner has stated that Firebase free tier must be preserved.

## Problem

Some robust guardrail designs require Cloud Functions or paid Firebase features.

## Options

1. Upgrade Firebase and use backend functions for authoritative workflows.
2. Stay free tier and enforce as much as possible through RTDB rules and client repair.

## Decision

Stay on free-tier-compatible RTDB rules and client-side repair unless explicitly changed.

## Consequences

- Rules must be heavily tested.
- Some quotas and cleanup are best effort.
- Architecture must avoid depending on paid-only backend workflows.
